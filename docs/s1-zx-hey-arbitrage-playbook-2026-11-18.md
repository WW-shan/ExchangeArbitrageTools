## 1. 他的方法拆解（6 条规则）

| #   | 规则                     | 含义                                 |
| --- | ------------------------ | ------------------------------------ |
| 1   | 选流动性差的币           | 流动性好的币不会插针，也就没有差价   |
| 2   | 目标是"插针"而非正常价差 | 一边骤跌 50%，另一边没动             |
| 3   | 币是媒介，不是信仰       | 只要不归零，持有库存是成本而非风险   |
| 4   | 常备双边库存             | 哪边插针就能立刻卖/买，不靠临时搬币  |
| 5   | 分批出货，吃尾部         | 他的工具在 0.5U 卖光，错过 9U 的尾部 |
| 6   | 24h 机器监控             | 人工不可能抓住秒级插针               |

## 2. 与我们系统的逐项对照

| 维度     | 他的做法           | 我们现状               | 差距             |
| -------- | ------------------ | ---------------------- | ---------------- |
| 目标函数 | 尾部事件（+100%）  | 常态小价差（0.3-0.7%） | **目标函数错位** |
| 币种范围 | 一篮子低流动币     | 单一 WARD              | 幅度不够         |
| 库存     | 双边常备           | 单边，追求零残留       | 无法双向响应     |
| 出货     | 分批，留尾部       | 一次性 FOK 全平        | **吃不到尾部**   |
| 信号     | 异常行情触发       | 每 5s 扫描固定阈值     | 缺少异常检测     |
| 风险态度 | 接受持有不归零的币 | 不允许残留             | 风险偏好相反     |

## 3. 根因：我们在优化错的目标

24h 实盘：10 笔 S1，6 胜 +0.1374，4 负 -0.1548，净 **-0.0174 USDT**。
平均盈利 0.0229 vs 平均亏损 0.0387（**1.69 倍**）。

原因不是执行差，而是：**在 40-70 bps 的目标上，一次失败要两次成功才能抹平**。
他在 10000 bps 的目标上，一次成功抵得上十几次失败。

结论：**在当前仓位规模下，提高单笔幅度的收益远大于提高胜率**。

## 4. 改造方案

### P0 插针扫描器（只读，零风险）

新增独立只读任务：

- 拉 Gate + Bitget 全部 USDT 交易对的 bid/ask（已验证可用）
- 每 3-5s 采样，记录每个币的**跨所最大偏离 bps**、持续时长、恢复时间
- 按"24h 内 >20% 偏离次数"排名，产出候选池
- 结果写 `data/dislocation-rank-*.json`

这一步直接回答：**WARD 到底有没有插针**。如果没有，就应该换币，而不是继续优化执行。

### P1 资产身份校验（必须先做）

447 个共同 USDT 交易对中，23 个显示 >100 bps 的"机会"，绝大多数是**同名不同币**
（RAIN / LIT / CRO / WEETH 在两个所根本不是同一个资产）。必须用**合约地址 + 链**做身份匹配，不能用 ticker。

### P2 分批出货（需资金支持）

当前总资金 ~20 USDT，Gate 最低名义 3 USDT。一笔 6.6 USDT 只能分 2 档，意义不大。
**但他的工具本身也是单档，仍在 60U/天** —— 说明起点不需要分批，需要的是**幅度**。

### P3 双边常备库存

现在 Gate 6929 WARD / 0.58 USDT，Bitget 5631 WARD / 7.15 USDT：两边都是币重、U 少，只能卖不能买。
要支持双向插针，每个所需同时持有 WARD 和 USDT。

## 5. 不建议做的事

- 不要继续在 WARD 上加价格缓冲、提高净利门槛 —— 那是在优化一个本身就没肉的目标
- 不要用 ticker 做跨所匹配
- 不要在没看到插针数据前放大仓位
