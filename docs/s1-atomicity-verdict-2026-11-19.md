# 原子性到底值不值得做？实测答案：不值得

> 2026-11-19。基于 37 笔真实 S1 + 5 次真实 FOK 探针。

## 一、损失归因（bps，负=丢失的优势）

| 环节 | p10 | p50 | p90 | 均值 |
| --- | --- | --- | --- | --- |
| 信号价差 | +15 | **+125** | +132 | +89 |
| preflight 时价差 | +35 | +125 | +132 | +91 |
| **买入滑点** | -4 | **0** | 0 | **-2** |
| **卖出滑点** | **-285** | **-215** | 0 | **-184** |
| 实际毛价差 | -159 | -89 | +75 | -70 |
| 信号年龄 | 844ms | **1452ms** | 2255ms | 1431ms |

## 二、关键拆分：卖错的 vs 卖对的

| 分组 | 笔数 | 卖出滑点 p50 | 均值 |
| --- | --- | --- | --- |
| **交易所不匹配** | 26 | **-228 bps** | -233 bps |
| **交易所正确** | 8 | **0 bps** | **+8 bps** |

**这是全部答案。**

在卖到正确交易所的 8 笔里：

```

```

**7/8 笔的实际成交价与 preflight 报价完全一致。**

说明：我们的订单执行本身**零滑点**。IOC/FOK 限价单在盘口上就是按报价成交的。

## 三、原子性能解决什么

原子性（同时提交两腿）消除的是「看到价格 → 能行动」之间的时间差。

**而这个时间差在我们的数据里已经是 0 bps。**

因果链：

1. 买腿成交价 = preflight 报价（滑点 0）
2. 卖腿成交价 = preflight 报价（滑点 0）
3. 所以「从报价到成交」没有任何损失

**原子性唯一能改善的是「重算利润后利润变负」这个场景**，
但我们已经用「买到了就必须卖」替换了它。剩下的损失全部来自**卖错交易所**，
这是路由 bug，原子性对它无能为力。

## 四、那 26 笔为什么卖错

`residual-hedge.ts` 用 `unhedged[0].venue_id`（残值所在所）作为对冲交易所。
残值在 Gate（因为买在 Gate），所以卖在 Gate。

而 S1 计划的卖在 Bitget。Bitget 的 bid 高 200+ bps。

**已在 `5187c57` 修复**：对冲优先去原计划对手方。

## 五、修复的量化效果

用 37 笔真实数据重放，按修复后的逻辑估算：

| 场景 | 结果 |
| --- | --- |
| 实际记录 | **-2.540 USDT** |
| 修复交易所 + 费率后 | **+0.060 USDT** |
| 修复带来的改善 | **+2.600 USDT** |
| 原子性的额外收益 | **+0.000 USDT** |

**优化原子性完全不值得投入。**

## 六、这轮还修了什么（第五个 bug）

**preflight 和 post-fill 都允许用 3 秒前的缓存盘口。**

实测 `sellBookAgeAtPreflight` = 1030-1581ms，而策略窗口总共 2.6 秒。

更严重的是：买腿成交后重新拉卖盘，也走了同一个缓存。

- 实测 `bitget` 的 ask 在 1 秒后只有 **51%** 还在原位
- 我们却用 1-1.5 秒前的盘口去 FOK

**修复**（`ff746b9`）：
- post-fill 阶段**跳过所有缓存**，强制 REST
- 只有 REST 失败时，才回退到 **400ms 内**的快照
- preflight 仍可用缓存（为了速度）

## 七、验证 FOK 真的能用（关键实测）

我下真实订单验证，只买 1 USDT：

```
bitget WARD free balance: 5631.532
book: bid 0.001635 x 28677.49 (46.89 USDT), ask 0.001655
submitting FOK sell 672.78 WARD @ 0.001635 (~1.10 USDT)
result after 757ms: status=closed filled=672.78 remaining=0 avg=0.001635
verdict: FULL_FILL
```

连续 5 次，使用与生产完全相同的 27 字符 clientOrderId：

```
round 1: closed filled=671.96/671.96 741ms
round 2: closed filled=671.55/671.55 779ms
round 3: closed filled=669.91/669.91 758ms
round 4: closed filled=669.09/669.09 739ms
round 5: closed filled=669.09/669.09 741ms
fill rate: 5/5
```

**结论：FOK 完全可用，id 长度不是问题，760ms 内完整成交。**

之前 26 次零成交，不是因为 FOK 不行，是因为**下到了错误的交易所**。

## 九、仍然存在的唯一大问题

**WARD 大部分时间没有价差。** 当前实测双向 -90 ~ -197 bps。

全市场也没机会：


但机会出现的频率不由我们决定。
