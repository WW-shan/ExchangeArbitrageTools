# 为什么那些 10% 的价差都是假的（实测结论）

> 2026-11-19。基于 24h 真实盘口 + Gate/Bitget/WEEX 实时探测。
> 这份文档推翻了我之前"去找大价差"的结论，并给出正确的筛选顺序。

## 0. 一句话

**大价差不等于机会。价差之所以大，几乎总是因为价差无法被抹平。**
我们 24h 数据里最大的几个"机会"，100% 属于以下三类陷阱，没有一个是能赚钱的。

## 1. 三类假机会（全部实测）

### 1.1 BREV：12.3% 的价差，因为 Bitget 不让提币

24h 里 Gate ↔ Bitget 的 BREV 价差：

| 指标 | 值 |
| --- | --- |
| 采样数 | 368 |
| 中位数 | **1232 bps（12.3%）** |
| p10 / p90 | 622 / 1567 bps |
| 全部 > 600 bps | 368/368 |

看起来是印钞机。但查 currencies 接口：

| 交易所 | 链 | 提币 | 充值 |
| --- | --- | --- | --- |
| Gate.io | ERC20 | ✅ | ✅ |
| Gate.io | BSC | ✅ | ✅ |
| Bitget | ERC20 | **❌ 关闭** | ✅ |

**Bitget 的 BREV 提币是关闭的。** 这个 12% 永远不会收敛，因为没人能把币从 Gate 搬到 Bitget 去卖。
谁去买 Gate 的"便宜"BREV，谁就拿到一个只能在 Gate 内部消化的仓位。

### 1.2 WEEX：一切大价差，因为数据延迟 132 秒

实测 WEEX ticker 时间戳比当前时间早 **132,172 ms**（2分12秒），1788 个 ticker 全部如此。

盘口层面同样：34 秒内 15 次 REST 采样，WEEX 的最优买卖价**一次都没变**：

```
weex     books= 15 unique=  1 changes=  0 span=34.2s
gateio   books= 15 unique= 12 changes= 12 span=34.3s
bitget   books= 15 unique= 15 changes= 14 span=35.7s
```

Gate/Bitget 每次采样都在变，WEEX 一动不动。这不是"盘口稳定"，是**喂给我们的快照是死的**。
拿它算价差，等于拿昨天的价格和今天比。

### 1.3 历史回放的"272 个 spike"，是同一段冻结行情

用初版检测器跑 24h 历史，得到 272 个"可交易 spike"，全部是 BREV。
但检查那段价格轨迹：WEEX 连续几十分钟停在 0.1018/0.10257，Gate 在 0.104~0.114 之间正常波动。
检测器把"不动的 WEEX"当成了可信参照，把"在动的 Gate"当成了插针——方向正好反了。

## 2. 全部共同币的可转移性普查

Gate ∩ Bitget，1866 个共同 ticker：

| 分类 | 数量 | 占比 |
| --- | --- | --- |
| **可双向提币**（真正可搬） | **425** | 22.8% |
| 不可双向提币 | 1441 | **77.2%** |

**接近八成的两所共同币，是不能双向搬运的。**
所有 10% 级别的"机会"都落在这 1441 个里——这是结构性的，不是巧合：
价差大 → 因为搬不动 → 搬不动 → 价差一直大。

## 3. 正确的筛选顺序（这个顺序不能颠倒）

之前我们的顺序是「先找价差 → 再看别的」，这是错的。正确顺序：

1. **可转移性**：两边都能提币 + 都能充值 + 同链同合约地址。不满足直接淘汰。
   - 这一步会砍掉 77% 的候选。
2. **数据活性**：该交易所的 ticker 延迟 < 阈值，且盘口在最近 N 次采样里变过。
   - 这一步会砍掉 WEEX 这类"看起来有货"的所。
3. **价差**：此时再算价差才有意义。
4. **可成交深度**：盘口能吃的量，扣完手续费还剩多少。

我们把它实现成了 `packages/core/src/transferability.ts` + `book-liveness.ts` + `dislocation.ts`，
扫描器 `scripts/scan-dislocation.ts` 严格按这四步执行。

## 4. 现在的扫描器会报什么

加了上述过滤器后跑 8 轮（全市场 600 个跨所 base）：

| 结果 | 次数 |
| --- | --- |
| 因交易所延迟被拒 | 5232 |
| 因无法双向提币被拒 | 504 |
| 因盘口冻结被拒 | 88 |
| 价差低于 500 bps | 2336 |
| **确认可交易的 spike** | **0** |

结论：**在 Gate/Bitget/WEEX 这三个所、当前这个时间点，"插针套利"没有可执行样本。**
不是因为没扫描到，而是因为扫描到的大价差全部过不了前三关。

## 5. 那什么才是真的能赚钱的

按证据强度排序：

### 5.1 有真实往返通道的币，做正常 S1（几十 bps）

425 个可双向提币的币里，存在真实但幅度小的价差。这类机会：
- 幅度通常 10~80 bps；
- 需要低延迟（我们实测端到端 2.6s，p90 5.4s，这是硬伤）；
- 单次利润薄，靠频次。

### 5.2 WARD：已验证的库存滚动

WARD 两所同链同地址（Base），但我们实测 Bitget 提 WARD 最低 5824 枚 ≈ 全部持仓，
所以实际也搬不动，只能靠两边常备库存做双向。这是我们目前唯一跑通的实盘路径。

### 5.3 真正的插针需要什么条件

要让插针套利成立，必须同时具备：
1. 该币**可双向提币**（否则价差不收敛）；
2. 触发所**数据不延迟**（否则看到的是历史价）；
3. 盘口**有真实深度**（否则吃不到）；
4. 我们的端到端延迟 < 插针持续时间。

目前第 1、2 条就把 WEEX/BREV 这类全部排除了。
剩下 425 个可搬的币里，需要长期扫描才能知道有没有真插针——这需要跑满 72 小时。

## 6. 对之前结论的修正

我在 `s1-dislocation-plan-2026-11-18.md` 里写的"WARD 至少出现 3 次 >=20% 偏离"这类判据，
现在看是**建立在错误数据上**的：那些 20% 偏离全部来自 WEEX 的过期快照。

正确的判据应该是：

> 在**可双向提币 + 数据延迟 < 5s + 盘口活跃**的币对集合里，
> 统计 >= 500 bps 的 spike 出现频率。这个集合目前有 425 个币。
