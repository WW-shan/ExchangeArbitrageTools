# 插针套利改造计划（Dislocation Strategy）

> 依据：@zx_hey 2026-11-18 三条搬砖推文 + 本仓库 24h 实盘数据 + Gate/Bitget 全市场快照实测。
> 本文是可执行计划，每个阶段都有验收标准（Definition of Done）。

## 0. 一句话结论

我们不是在优化执行，我们在优化一个**错误的目标函数**：

|            | 他                    | 我们                   |
| ---------- | --------------------- | ---------------------- |
| 单笔幅度   | +107%（1.87U → 3.9U） | +0.3~0.7%（40~70 bps） |
| 胜负代价比 | 1 次成功 ≈ 十几次失败 | 1 次失败 = 2 次成功    |
| 结果       | 60U/天（他自己说）    | 24h 净 -0.0174 USDT    |

**40 bps 的目标上，执行再快也赚不到钱；10000 bps 的目标上，慢半拍也能赚。**

## 1. 已核实的事实（不是推测）

### 1.1 资产身份可以精确校验

两边 currencies/coins 接口都返回合约地址，实测 WARD 完全一致：

| 交易所  | 链      | 合约地址                                   |
| ------- | ------- | ------------------------------------------ |
| Gate.io | BASEEVM | 0x174a0de0fa1c4771ca980a42553c0041016e5a67 |
| Bitget  | BASE    | 0x174a0de0fa1c4771ca980a42553c0041016e5a67 |

Gate 侧有 3235 个币带 EVM 地址，覆盖率足够。

### 1.2 同名不同币是真实存在的陷阱

447 个共同 USDT 交易对里，23 个显示 >100 bps，其中绝大多数是同名不同资产
（RAIN / LIT / CRO / WEETH 两边根本不是同一个币，价格差 100%~4577%）。
**任何扩池动作之前必须先做身份校验，否则等于随机买别人的币。**

### 1.3 流动性分层（Gate ∩ Bitget，共 447 对）

| 双边 24h 成交额 | 交易对数 | 备注               |
| --------------- | -------- | ------------------ |
| < 1K USDT       | 15       | 极低流动           |
| 1K – 10K        | 117      | 低流动，插针高发区 |
| 10K – 100K      | 209      | **WARD 在这里**    |
| 100K – 1M       | 75       | 中流动             |
| > 1M            | 32       | 高流动，几乎无插针 |

WARD 在 10K–100K 档，属于插针有可能但频率不高的档位。这是需要实测确认的关键问题。

### 1.4 现有过滤器会直接拦掉插针

`packages/core/src/s1.ts:210` 的 `suspicious_spread_bps = 1000`（10%）。
而插针目标是 20%~100%+。当前配置下，真正的插针机会会被当成"可疑"直接丢弃。
这是必须先改的硬编码冲突。

### 1.5 库存与提币的真实约束

| 项目                  | 数值         |
| --------------------- | ------------ |
| Gate WARD             | 6929.86      |
| Gate USDT             | 0.58         |
| Bitget WARD           | 5631.53      |
| Bitget USDT           | 7.15         |
| Bitget 提 WARD 手续费 | 58.24 WARD   |
| Bitget 最低提 WARD    | 5824.11 WARD |

结论：WARD 基本无法跨所搬运（提现门槛 = 我们全部持仓）。
所以只能靠"两边常备库存"应对双向插针，不能靠搬币。

## 2. 设计原则

1. 先测量，再交易：没有插针统计数据之前，不动实盘逻辑。
2. 只读优先：扫描器完全不碰私钥，可以 7x24 跑。
3. 不破坏现有 S1：新策略是独立通道，S1 继续按原逻辑跑，可随时关掉。
4. 可回滚：所有新行为都由配置开关控制，默认关闭。
5. 不做未经验证的假设：每个阈值都从数据里来，不拍脑袋。

## 3. 分阶段计划

### 阶段 A：插针扫描器（只读，零风险）

目标：用真实数据回答"哪些币会出现跨所插针，多大幅度，多频繁"。

交付物：

- `scripts/scan-dislocation.ts`：独立 CLI，复用 createCexAdapter + createPublicRuntime
- `config/dislocation.toml`：采样间隔、偏离阈值、流动性区间
- `data/dislocation-rank-<ts>.json`：排名结果
- `docs/dislocation-findings-<ts>.md`：自动生成的结论报告

算法：

1. 每 N 秒（默认 5s）拉一次两所全量 ticker（fetchTickers，单请求，无速率压力）。
2. 用合约地址做身份匹配，只保留确认同一资产的交易对。
3. 对每个交易对计算双向可成交价差：`(bidB - askA) / askA` 与 `(bidA - askB) / askB`。
4. 记录超过阈值（默认 300 bps）的样本：时间、方向、幅度、两边报价。
5. 把连续超阈值的样本聚合成 episode（间隔 < 60s 视为同一段）。
6. 输出排名：按 episode 数 x 中位幅度 排序。

同时输出「WARD 专项结论」：它在 24h 内触发了几次、最大幅度多少、持续时间多长。

验收标准：

- 能连续跑 24h 不断线，内存稳定；
- 输出文件包含每个交易对的 episode 数、中位/最大幅度、中位持续时间；
- 报告能直接回答「WARD 值不值得继续做」。

### 阶段 B：资产身份校验（前置依赖）

交付物：

- `packages/venues/cex/src/asset-identity.ts`：把两所的 currencies/coins 归一化成 `{symbol, chain, address}`，地址统一转小写，链名做别名映射（BASEEVM / BASE -> base）。
- `scripts/verify-asset-identity.ts`：对任意 base 输出两所是否同一资产、链是否可互通。
- 在 scanner 的 universe 构建里接入：身份不匹配的交易对直接剔除。

验收标准：

- WARD 判定为同一资产（Base 链，同一地址）；
- RAIN / LIT / CRO / WEETH 这类同名不同币被判为不同资产并剔除；
- 有单测覆盖：同链同地址、同地址不同链、缺地址、无效地址四种情况。

### 阶段 C：插针信号与风控开关（仍不动实盘）

交付物：

- `packages/core/src/dislocation.ts`：纯函数，输入两所 ticker + 历史基线，输出 `{isDislocation, direction, magnitudeBps, fairValueDeviation}`。
- 判定逻辑（三条同时满足）：
  1. 跨所可成交价差 >= `minDislocationBps`（默认 2000 = 20%）；
  2. 触发所在交易所的价格偏离自身近 5 分钟中位数 >= `minVenueDeviationBps`（默认 1500）；
  3. 另一所偏离自身基线 < `maxCounterDeviationBps`（默认 500），用来区分「一所插针」和「整体重定价」。
- 单测覆盖：单边插针、两边同向、数据缺失、时间戳倒挂。

为什么需要第 3 条：只有两个交易所时，无法单靠价差判断谁错。
用「自身基线」做参照，才能区分「一所短暂故障」和「真实行情」。

### 阶段 D：执行与库存

这一步才碰实盘，且必须等阶段 A 的数据。

交付物：

- S1 之外新增 `strategy = 'DISLOCATION'` 的执行通道，复用现有协调器状态机（未知订单、部分成交、重启对账全部保留）。
- `suspicious_spread_bps` 改为按策略区分：S1 保持 1000，DISLOCATION 设为 0（不拦截）。
- 库存模型：
  - 每个所目标持有 `WARD` 与 `USDT` 各 50%；
  - 触发卖出后，用所得 USDT 在回落时补回；
  - 库存偏离超过 `maxInventoryDriftPct`（默认 30%）时暂停该方向。
- 分批出货：当单笔名义 >= 30 USDT 时，按 50/30/20 三档挂出；当前 6~10 USDT 规模下保持单档。

### 阶段 E：实盘灰度

- 先用最小名义（Gate 3 USDT 起）跑 20 笔，只做卖出方向（我们两边都是币重）。
- 每笔记录：信号幅度、下单延迟、成交价、实际利润、事后 5 分钟价格。
- 20 笔后对比「一次性全平」与「分批」的差异，再决定是否放大。

## 4. 决策门（Go / No-Go）

| 时点           | 判据                                                                          | 不满足时的动作                        |
| -------------- | ----------------------------------------------------------------------------- | ------------------------------------- |
| A 阶段 24h 后  | WARD 至少出现 3 次 >=20% 的跨所偏离，且中位持续时间 >= 30s                    | 换标的，在 1K-100K 档里按同样方法排序 |
| A 阶段 72h 后  | 候选池中至少 1 个币满足「每周 >=5 次、中位幅度 >=20%、可成交深度 >= 10 USDT」 | 停止该方向，回到 S1                   |
| C 阶段完成后   | 用历史 ticker 回放验证信号准确率 >= 60%                                       | 调整阈值，不进入实盘                  |
| E 阶段 20 笔后 | 净收益 > 0 且最大单笔回撤 < 2 USDT                                            | 停止放大，复盘                        |

## 5. 已知风险

1. **持仓归零风险**：低流动币可能下架、跑路。他的原话是"只要不归零就行"，但这是真实风险，必须设单币上限。
2. **两所局限**：只有两个价格源，无法完全区分"一所插针"与"整体重定价"。阶段 C 的基线判定是缓解手段，不是根治。
3. **提币不可行**：WARD 最低提现 5824 枚，等于全部持仓。库存只能在交易所内滚动。
4. **滑点**：ticker 只有最优价，没有深度。阶段 A 必须先记录深度，否则 20% 的价差可能只有 5 USDT 可吃。
5. **样本偏差**：插针是稀有事件，24h 数据可能不足以下结论，必要时延长到 7 天。

## 6. 明确不做的事

- 不为了"抓插针"而放宽未知订单、部分成交、重启对账的安全逻辑。
- 不用 ticker 直接下单，必须经过盘口深度确认。
- 不在没有 24h 数据前改实盘阈值。
- 不把 `suspicious_spread_bps` 全局关掉——只对 DISLOCATION 策略关闭。
